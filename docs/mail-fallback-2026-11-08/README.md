# 邮件入口反馈修复 · 2.4.2

2026-11-08，用户报告首页“发邮件给 Kevin”无反应。

排查三个方向：按钮遮挡/命中、JS取消默认动作、外部邮件处理器及页面反馈。浏览器命中测试为true，冒泡末端defaultPrevented=false，href保留正确mailto收件人与正文，旧页没有任何可见状态反馈。当前证据不能定位用户浏览器的默认邮件应用配置；无处理器、未允许协议请求等环境均可能使mailto看似无反应。不能把协议调用当成邮件撰写成功，更不表示发送成功。

修复：八语首页主按钮明确为“用邮件应用打开”。保留原生mailto默认行为，同时立即显示持久、可关闭的反馈：未打开时可复制地址或使用网页版Gmail。备用链接从当前mailto派生收件人、主题与正文，不自动开第二个目的地、不自动写剪贴板、不发送邮件。所有共享支持页的mailto同样获得反馈；切换语言会清理旧提示。原有复制失败可手工选择的能力保留。

验证：20项Node测试、16个新增八语/手机/桌面邮件场景、原16个多语交互与154布局组合通过。新增测试在window冒泡末端记录网站未取消默认动作，再模拟无外部处理器，验证键盘触发、默认动作保留、显式复制、剪贴板拒绝、Gmail模板与noopener、语言切换和窄屏提示无溢出。检查实际截图。测试没有发送邮件、登录邮箱或证明所有用户设备的邮件客户端均能打开。
